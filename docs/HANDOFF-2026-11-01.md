## Process rules from this session

**The `#![warn(missing_docs)]` attribute must be the first action of
any crate's doc-fix script.** Twice (kod-stats and kod-tui) the
campaign ran a fix script that did not enable the lint crate-wide,
`cargo doc -D warnings` returned 0 (because nothing was being
enforced), and the "clean" result was a false green. The real
missing-doc count only appears when `RUSTDOCFLAGS='-W missing-docs'
cargo doc` runs explicitly (from the recon) or when the attribute is
present. Adding the attribute first makes the trailing `cargo doc -D
warnings` meaningful.

**Name-based `insert_docs` on a file that also contains struct
literals will match the wrong thing.** `Self { id, .. }` and
`Variant { name, .. }` share the shorthand field syntax with struct
declarations. A name-based inserter that only matches identifiers on
a line will insert doc comments into expression contexts, and
`rustdoc` will report them as `unused_doc_comments`. Fix is
line-anchored insertion (using the recon's warning locations) or
content-anchored `block()` calls with surrounding context.

**A `block()` insertion that changes line counts invalidates every
subsequent line-anchored insertion in the same script.** Two scripts
in kod-core aborted because a `block()` inserted lines above other
`insert_docs` targets, shifting their anchors. Fix is either to run
`block()` first and re-run the recon, or to use content anchors
throughout.

**The `cargo doc -D warnings` gate catches link errors that
per-crate `cargo doc -p <crate>` does not.** The kod-core-serve
workspace gate failed once because a `[`serve_io`]` link in a README
resolved under `-p` (which has the crate in scope) but not under
`--workspace` (which resolves against the workspace root's included
files). Every batch verify ends with a workspace-wide `cargo doc -D
warnings` for this reason.

**A `git commit` that reports a lock error may have still
committed.** Twice this session a "fatal: Unable to create
'.git/index.lock'" message appeared while the commit landed anyway.
Verify by `git log -1` before retrying — a retry against an
already-committed tree will try to commit an empty diff.

**The full gate is four commands now, not three.** The doc gate
joined the existing fmt / clippy / nextest trio during this session.
`cargo doc --all-features --no-deps --workspace` under
`RUSTDOCFLAGS='-D warnings'` is a hard gate on the workspace.
