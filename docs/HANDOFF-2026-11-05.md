## Automation in place

`.github/workflows/changelog.yml` runs on every v* tag push:

1. Installs git-cliff
2. Generates CHANGELOG.md to /tmp
3. Five sanity gates: non-empty, no "(expected empty)", contains new tag, release count did not decrease, v0.1.0 preserved
4. Only then writes CHANGELOG.md and kod-docs/.../changelog.mdx
5. Opens a PR (never commits to main directly)

`cliff.toml` defines the format. Wrong category? Edit cliff.toml and
re-push the tag.

## Methodology that made this safe

1. Diagnostic-first: dump source before editing
2. Atomic writes: mkstemp + os.replace + read-back verify
3. Corruption guard: check for "(expected empty)" before and after every write
4. Three-way commit guard: unstaged OR staged OR untracked, not just git diff --quiet
5. HEAD-change detection for commit retry (external actor races on .git/index.lock)
6. File-based commit messages (git commit -F /tmp/msg)
7. Brace-walking for structured extraction
8. Python for regex, shell for file ops
9. Skip-on-shape-mismatch: partial-apply, report what didn't land
10. Verify with a follow-up batch: never trust a batch's own output

## Known gotchas

- External cargo-watch actor commits staged state using /tmp/*.msg files.
  Use HEAD-change retry loop; do not clean it up as dead code.
- git diff --quiet only checks unstaged. A staged-only state reads as clean.
  Use the three-way guard.
- clippy --all-targets doubles counts; unique-site counts are authoritative.
- "(expected empty)" in a file = atomic-write contract violated.
- md.relative_to(Path.cwd()) crashes on relative vs absolute mismatch.
  Always .resolve() both sides.
- git-cliff default body template emits triple-blank-lines between
  heading and first bullet. cliff.toml in this repo has the fixed body.
