## Verdict — KEEP adk-model

**KEEP adk-model.** All three questions answered yes; the spike's working
hypothesis (REPLACE) was wrong and is retracted here.

### Q1 — multi-role messages: **YES**

`Content::new(role)` takes an arbitrary role string. Every provider
converter maps the standard set explicitly:

- `openai/convert.rs:99,122,126` — `"model"|"assistant"`, `"system"`,
  `"function"|"tool"`.
- `anthropic/convert.rs:40-41` — `"user"|"function"|"tool"` → `MessageRole::User`,
  `"model"|"assistant"` → `MessageRole::Assistant`.
- `groq/convert.rs:164-167`, `deepseek/convert.rs:212-215`,
  `bedrock/convert.rs:55-71` — same three-way split.
- `gemini/interactions_convert.rs:337` — `content.role == "system"` handled
  separately.

`LlmRequest::new(model, Vec<Content>)` accepts the multi-role vector.
The kotlin-style `Content::new("user").with_text(prompt)` shape currently
used by `OpenAICompatProvider::text_request` was a simplification, not a
limitation.

### Q2 — tool calls with ids: **YES**

`Part::FunctionCall { name, args, id: Option<String>, thought_signature }`
already carries the id field. `tool_call_parser.rs` (used only for models
that emit tool calls as text tags) always sets `id: None`, which is
correct for that path. The OpenAI wire parser is expected to populate
`id` from the SSE delta's `tool_calls[i].id` — to be confirmed by the
contract tests in A3, not by reading source.

### Q3 — distinct system prompt: **YES**

Per-provider handling, all correct:

- Anthropic: `anthropic/client.rs:179` extracts `role == "system"` into
  the Messages API's top-level `system` field.
- Gemini: `system_instruction` top-level field
  (`gemini/interactions_convert.rs:281-282`).
- Bedrock: `system: Vec<SystemContentBlock>` on the request
  (`bedrock/convert.rs:29-30`).
- OpenAI-compatible: a `role: "system"` message, which is the OpenAI
  chat-completions spec.

## Unexpected finding — Anthropic client is already present

`adk-model 2.2` ships a native Anthropic client (`anthropic/client.rs`,
`anthropic/config.rs`, `anthropic/convert.rs`), plus Gemini, Bedrock,
Groq, DeepSeek, Ollama, OpenRouter, and Azure AI. The A5 provider
becomes a ~80-line wrapper around `adk_model::anthropic::Anthropic`
(mirroring the shape of `OpenAICompatProvider` around
`adk_model::openai_compatible::OpenAICompatible`), not a ~400-line
native Messages API client. Effort estimate for A5 drops from L to S.
