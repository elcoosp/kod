# ADR-05 — Native Anthropic wire, not an adk-model wrapper

Status: accepted
Date: 2026-09-30

## Context

`kod-provider-openai` and `kod-provider-anthropic` were both built as
thin wrappers over `adk-model 2.2`. For the OpenAI-compatible provider
that works: `adk_model::openai_compatible::OpenAICompatible` passes the
message and tool arrays through in the shape the wire needs, and
`kod-provider-openai` is a genuine wrapper today.

For Anthropic it does not. `adk-model`'s `AnthropicClient` accepts a
single `system: String` and flattens a multi-segment system prompt
before the wire call. Anthropic's prompt-caching contract places
`cache_control: {"type": "ephemeral"}` on a **block inside a system
array**, not on a top-level string. Once `adk-model` has flattened the
prompt, the breakpoint cannot be placed — and the cache write premium
(1.25x) is paid on every request for a cache that is never read back at
the discount (0.1x).

The spike ADR-04 evaluated `adk-model 2.2` for the D1 refactor and
scoped a native `wire.rs` as the fallback if the wrapper could not
express what the design needed. It could not.

## Decision

`kod-provider-anthropic` builds its request bodies in a local `wire`
module for every path the design's cache and compaction work touches:

- `wire::build_messages_body` — the non-streaming `complete` path.
- `wire::build_streaming_body` — the streaming loop.
- `wire::build_compaction_body` — the `compact-2026-01-12` beta.

`wire::system_blocks` emits the structured system array and places the
breakpoint on the last cacheable segment, which is exactly the
invariant prefix the design's golden-prefix test protects.

The legacy text paths (`generate` / `generate_with_tools`) keep using
`adk_model::anthropic::Anthropic`. They predate the structured request
and carry no cache hints, so flattening costs them nothing.

`kod-provider-openai` stays a wrapper: its `adk-model` client passes
the structured shape through, so a native `wire` would be duplicated
code for no gain.

## What this does not change

- `typesafe-ai-rs` is unrelated to this decision. It is the **Jev**
  client (`kod-core/src/jev.rs`) — a separate, complementary system
  used for judgment calls, not an LLM provider. It stays.
- `adk-model` stays a dependency of both provider crates. For
  `kod-provider-anthropic` it supplies the legacy text path; for
  `kod-provider-openai` it supplies the whole implementation.
- ADR-04 is generated by `scripts/spike-adk-model.sh` and is marked
  "do not hand-edit". Its `A2 replaces adk-model with a native
  wire.rs` line is the *spike's* plan; this ADR records that the plan
  was taken for Anthropic only, and not for OpenAI.

## Consequences

- Cache breakpoints are correct on every path a user's session takes
  through Anthropic.
- Two wire-building code paths exist in `kod-provider-anthropic` (the
  native `wire` module and the `adk-model` legacy path). The crate
  header names both; the module docs of `wire.rs` explain the split.
- If `adk-model` ever exposes a structured-system API, the native
  `wire` module could be retired for that path. Until then it stays.
