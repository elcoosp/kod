Compaction shrinks a transcript so the next turn fits in the model's context window. `/compact` triggers it; the engine also runs it after a turn when the window is nearly full.

## When it fires

`used_tokens + reserve > window_tokens`, where `reserve = max(15% of window, 16_384)`.

A 200k window reserves 30k, so compaction starts around 170k used. A zero window never compacts — refusing is the safe reading when the window is unknown, and the caller learns the real number on the next provider call.

`/context` shows the live breakdown; the status line's context meter is the same number.

## What actually runs

Compaction is a preference list with fail-over, not a hardcoded ladder. The dispatcher holds an ordered set of methods and asks each whether it can reduce the context; the first that produces a non-empty plan wins.

The engine installs **three** methods, in this order:

| Order | Method | What it does |
| --- | --- | --- |
| 1 | `shake` (aggressive) | replaces large byte ranges inside tool results with a placeholder |
| 2 | `prune` | drops whole messages a later message supersedes |
| 3 | `handoff` | an LLM-written handoff document, when neither mechanical rung reduces enough |

The ordering is deliberate. The engine's dispatcher fires only *after* the threshold decision — the transcript is already too big, so the choice is "reduce now, or pay for a summary call". Under that pressure a cheap mechanical elision that clears the threshold beats an expensive LLM call. So the mechanical rungs go first and `handoff` catches what they cannot.

`shake` runs in its **aggressive** configuration here (protect 4,000 tokens, savings gate 0) rather than the default one. The default config assumes an opportunistic call on an otherwise-clean session, where "no reduction" is a fine outcome; under the engine's threshold regime, no reduction means a round-trip to the summariser.

The dispatcher's `default_ladder()` — `remote`, `snapcompact`, `handoff`, `shake`, `soft` — is the design's ordering for a deliberate compaction, not what the engine installs. Three of its five methods are stubs returning "unavailable": `remote` (provider-native compaction), `snapcompact` (bitmap-frame imaging), and `soft` (local-LLM summary). `shake` and `handoff` are real.

## What `/compact` does

`/compact` is a **separate path** from the automatic threshold compaction above. It does not run the dispatcher ladder at all.

It keeps the last 20 turns and replaces everything before them with a summary message, pinned so the render path cannot drop it for budget reasons. The summary is the same factual `emergency_summary` the hard-threshold path falls back to — message count, tools used, file paths — with no attempt to explain intent.

<Aside type="note">
  Before this was fixed, `/compact` silently truncated: the dropped turns left nothing behind, so file paths, decisions and facts from them vanished from the model's view entirely. The automatic path had always summarised, so the two paths doing the same job had different consequences.
</Aside>

A summary is deliberately factual rather than an LLM-written recap: it runs synchronously, and a model call there would make an interactive command wait on the network. If you want the transcript summarised by the model, let the automatic path run — its `handoff` rung does exactly that.

## Shake in practice

Shake replaces large byte ranges inside tool results with a placeholder, keeping the message and its metadata. A 40 KB `read_file` result becomes a short line saying how many bytes were elided.

Two guards stop it destroying things it should not touch:

- **`protect_tokens`** (16,000 by default) — recent context is left alone even when large, because the model is probably still working with it. Shake's default is lower than prune's, since shake's mutations are smaller and more scattered.
- **`cache_warm_suffix_tokens`** (8,000 by default) — a suffix inside the provider's warm cache is not touched. Invalidating it would cost more than the tokens saved.
- **A whole-plan savings gate** — a pass that frees fewer than a threshold number of tokens is skipped outright, because the cache churn is not worth it.

Per-turn protected paths (files the turn is actively touching) are merged into the method's own config, so a file being edited is not shaken mid-turn.

## Plans, not mutations

Every method returns a *plan* — a description of the mutations — not a mutated transcript. The caller applies it. That keeps the methods pure and testable without an engine, and it means a plan can be rejected before anything changes: a plan that does not actually shrink the transcript is refused.
