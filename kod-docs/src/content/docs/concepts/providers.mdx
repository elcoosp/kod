KOD talks to models through one abstraction: the `LlmProvider` trait in `kod-provider`, implemented today by `kod-provider-openai` (backed by `adk-model`). The design bet is that almost every model server you might run locally — and OpenAI itself — speaks the same OpenAI chat-completions wire protocol, so one implementation covers all of them.

## One code path, many servers

All of these work unchanged, on the same code path:

<Tabs>
<TabItem label="Ollama (default)">
  ```toml
  [[llm.endpoints]]
  name     = "local"
  provider = "openai-compatible"
  base_url = "http://localhost:11434/v1"
  model    = "qwen2.5-coder:7b"
  context_window = 32768
  ```
</TabItem>
<TabItem label="LM Studio">
  ```toml
  [[llm.endpoints]]
  name     = "lmstudio"
  provider = "openai-compatible"
  base_url = "http://localhost:1234/v1"
  model    = "your-model"
  context_window = 16384
  ```
</TabItem>
<TabItem label="vLLM">
  ```toml
  [[llm.endpoints]]
  name     = "vllm"
  provider = "openai-compatible"
  base_url = "http://localhost:8000/v1"
  model    = "your-model"
  context_window = 32768
  ```
</TabItem>
<TabItem label="OpenAI (cloud)">
  ```toml
  [[llm.endpoints]]
  name     = "openai"
  provider = "openai-compatible"   # "OpenAI" works too — same thing
  base_url = "https://api.openai.com/v1"
  model    = "gpt-4o-mini"
  api_key_env = "OPENAI_API_KEY"   # the key lives in the environment
  context_window = 128000
  ```
</TabItem>
</Tabs>

The `provider` field accepts `openai-compatible` (aliases `Ollama` and `OpenAI`). An `anthropic` kind is recognised in config but not implemented yet — it fails at the first prompt, and a startup warning makes the gap visible before the session rather than during one.

## Endpoints, not a single model

Endpoints are a list, and the first one is the default. Everything that affects the wire — `base_url`, `model`, `temperature`, `max_tokens`, `timeout_secs` — lives on the endpoint, which is what lets [routing](/guides/configuration/#endpoints-instead-of-a-single-model) send a swarm's planning to one server and its coding to another. API keys are referenced by environment-variable *name* (`api_key_env`), so a committed config cannot leak a secret, and optional `[llm.endpoints.pricing]` (USD per million tokens) feeds the TUI's cost display.

## Base-URL normalisation

Base URLs are normalised automatically: a server root (`http://localhost:11434`) or an `.../v1` root (`http://localhost:11434/v1`) both work. KOD composes the correct chat-completions endpoint either way, which removes the most common "connection works but requests 404" footgun when switching servers.

## Streaming and tool calls

Generation is streaming-first. The provider consumes SSE and emits chunks the UI renders live; tool calls get special treatment with `ToolCallStart` / `ToolCallDelta` framing, so a tool call is **assembled live as the model emits it** rather than buffered until the response completes. By the time the model finishes its turn, KOD already has the call ready to gate and execute — one reason the TUI's tool rows feel immediate.

Non-streaming generation exists too, but the engine's loop uses streaming everywhere, including inside [swarm](/guides/swarm/) agents.

## Model discovery

`kod models` calls the provider's `list_models()` (`GET /v1/models` upstream) with `--filter` to narrow the list. Errors are surfaced rather than collapsed into an empty list — a bad endpoint shows up as an error here instead of mysteriously showing "no models". The TUI's `/model` completion uses the same source, so the names it offers are the ones your server actually serves.

## What a provider must provide

The trait surface is deliberately small: generation (streaming and not) with tool calling, plus model listing. `GenerationOptions` carries temperature, token caps, and friends. That smallness is why the OpenAI-compatible path covers so many servers — and why a future second implementation (Anthropic's native protocol, for instance) has a clear shape to slot into.

<Aside type="note">
  Engine detail worth knowing: the agentic loop does not hold the provider read lock across a streaming round, so <code>/model</code> mid-prompt switches instantly — one endpoint's stream can wind down while the next spins up.
</Aside>
