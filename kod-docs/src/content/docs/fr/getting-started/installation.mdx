KOD est distribué sous forme d'un seul binaire Rust que vous compilez depuis les sources. Il n'y a pas de paquet à télécharger depuis un registre et pas de runtime à installer : `cargo build --release` compile l'agent, les outils, le stockage en mémoire et l'interface du terminal en un seul exécutable à `./target/release/kod`.

## Prérequis

Trois choses doivent être présentes sur votre machine avant de compiler :

- **Rust 1.98.1 ou plus récent**, installé via [rustup](https://rustup.rs/). L'espace de travail utilise l'édition 2024, donc les anciennes chaînes d'outils refuseront de le compiler. La MSRV (`1.98.1`) est déclarée dans `Cargo.toml` sous `[workspace.package].rust-version` ; `rust-toolchain.toml` épingle le canal `stable` plus les composants `rustfmt` et `clippy` pour un outillage reproductible.
- **Un serveur de modèle** qui parle le protocole de complétion de chat OpenAI. [Ollama](https://ollama.ai/) est le défaut recommandé et ce que les profils fournis ciblent en premier, mais LM Studio, MLX Omni Serve, vLLM et OpenAI lui-même fonctionnent tous sans modification.
- **Git**, requis à la fois pour les outils git intégrés (`git_status`, `git_diff`, `git_commit`, `git_branch`) et pour `build.rs`, qui estampille les informations de version dans le binaire au moment de la compilation.

Deux extras optionnels débloquent plus de choses plus tard : [bubblewrap](https://github.com/containers/bubblewrap) (`bwrap`) sous Linux pour `--sandbox`, et tout [serveur de langage](/guides/tools/#write-follow-ups-lsp-and-check) sur votre `PATH` (rust-analyzer, typescript-language-server, …) pour les outils LSP. Aucun n'est requis pour démarrer.

## Compiler depuis les sources

<Steps>
1. Clonez le dépôt et compilez l'espace de travail en mode release :

   <Code lang="bash" code={`git clone https://github.com/elcoosp/kod.git
cd kod
cargo build --release`} />

2. Confirmez que le binaire est là et s'exécute :

   <Code lang="bash" code={`./target/release/kod --version`} />

3. Optionnellement, mettez-le sur votre `PATH` :

   <Code lang="bash" code={`cp ./target/release/kod ~/.local/bin/   # or another directory on PATH`} />
</Steps>

L'espace de travail compile sous Linux, macOS et Windows. Une compilation de débogage (`cargo build`) est suffisante pour essayer, mais la boucle d'outils en streaming est sensiblement plus rapide en mode release.

## Premier lancement

KOD n'a besoin d'aucune configuration pour démarrer — chaque paramètre a un défaut sain — mais deux commandes existent spécifiquement pour rendre les cinq premières minutes fluides.

### `kod doctor`

`kod doctor` imprime un rapport de diagnostic couvrant le fichier de configuration, l'endpoint du modèle, les compétences découvertes, la base de données de mémoire, la primitive de bac à sable et git. C'est le moyen le plus rapide de répondre à « est-ce que ma configuration fonctionne réellement ? » sans lancer une session, et il sort avec un code non nul si une vérification échoue — vous pouvez donc aussi l'utiliser pour bloquer un script :

<Code lang="bash" code={`kod doctor            # human-readable report
kod doctor --json     # machine-readable, for scripts
kod doctor --fix      # create missing directories, write a default config`} />

`--fix` ne modifie jamais un fichier de configuration existant ; il ne remplit que ce qui manque.

### `kod init`

`kod init` imprime où vit la configuration, les profils de modèle vers lesquels vous pouvez basculer, et les trois prochaines commandes qu'un nouvel utilisateur devrait exécuter. C'est idempotent — l'exécuter deux fois ne change rien. Avec `--force`, il réécrit la configuration à partir des défauts (en sauvegardant l'ancienne) :

<Code lang="bash" code={`kod init
kod init --force      # reset to defaults, backing up the current file`} />

### Pointer KOD vers un modèle

Les profils de modèle regroupent un nom de modèle, une URL de base, une fenêtre de contexte et des paramètres de génération dans un préréglage afin qu'un utilisateur de première exécution n'ait pas à savoir ce qu'est un `context_window`. Les préréglages intégrés sont `local-fast` (Qwen 2.5 Coder 7B), `local-capable` (32B), `local-reasoning` (DeepSeek-R1 14B) et `cloud-openai` (GPT-4o mini) :

<Code lang="bash" code={`ollama pull qwen2.5-coder:7b    # one-time model download
kod profile use local-fast      # writes the preset into config.toml`} />

<Aside type="tip">
  Les profils locaux listent leur commande d'installation en une ligne (`ollama pull …`) directement dans `kod profile list`, donc vous pouvez copier-coller sans quitter le terminal.
</Aside>

### Démarrer une session

<Code lang="bash" code={`kod tui`} />

La TUI s'ouvre, restaure votre session précédente si vous en avez une, et vous accueille avec le modèle chargé et le nombre de compétences. Si vous préférez un REPL simple, `kod chat` vous donne le même agent dans un shell scriptable.

## Complétions shell

KOD peut imprimer un script de complétion pour votre shell, prêt à être sourcé :

<Tabs>
  <TabItem label="Bash">
    <Code lang="bash" code={`kod completions bash > ~/.local/share/bash-completion/completions/kod`} />
  </TabItem>
  <TabItem label="Zsh">
    <Code lang="bash" code={`kod completions zsh > ~/.zfunc/_kod`} />
  </TabItem>
  <TabItem label="Fish">
    <Code lang="bash" code={`kod completions fish > ~/.config/fish/completions/kod.fish`} />
  </TabItem>
  <TabItem label="Elvish / PowerShell">
    <Code lang="bash" code={`kod completions elvish
kod completions powershell`} />
  </TabItem>
</Tabs>

## Rester à jour

`kod update` vérifie GitHub pour une version plus récente et imprime l'URL et les instructions d'installation. C'est en lecture seule — il ne remplace jamais votre binaire. Pour mettre à jour, récupérez les dernières sources et recompilez avec les deux mêmes commandes que vous avez utilisées pour installer.

<Aside type="note">
  La recompilation après `git pull` est le chemin de mise à niveau prévu pour l'instant. Des artéfacts de release précompilés sont produits par le pipeline CI, mais la compilation depuis les sources reste l'installation canonique.
</Aside>
