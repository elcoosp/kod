The KOD workspace is a Cargo workspace with **26 crates** in **4 layers**,
from the most stable foundation to the outermost interface:

- **Foundation** — types, errors, config. No internal dependencies.
- **Engine** — the orchestration core and its five sub-crates under
  `kod-core-*`. See [Core crates](/concepts/core-crates/) for how the
  family fits together.
- **Capability** — providers, tools, skills, memory, transport, and the
  analysis crates (`kod-ast`, `kod-risk`, `kod-minimize`,
  `kod-schema-dialect`). Each is independently usable.
- **Interface** — the `kod` binary (`kod-cli`) and the terminal UI
  (`kod-tui`).

## Foundation

| Crate | Description |
|---|---|
| `kod-types` | IDs, message and tool types, roles, serialization, trust levels, redaction primitives. |
| `kod-error` | `KodError` — the single error enum threaded through every fallible API. |
| `kod-config` | `KodConfig` with its per-section types and mtime-validated TOML cache. |

## Engine

| Crate | Description |
|---|---|
| `kod-core` | The engine: agent loop, transcript, compaction dispatch, telemetry wiring, Jev advisor, swarm runner. |
| `kod-core-routing` | Task classification, context assembly, and model selection. |
| `kod-core-state` | Session persistence, file checkpoints, cost accounting, sensitivity classification. |
| `kod-core-serve` | ACP JSON-RPC server over a Unix-socket daemon, bridging the engine and editor clients. |
| `kod-core-quality` | `snapcompact`, `shake`, and `repomap` — analysis, compaction, and quality gates. |
| `kod-core-tools` | Adapter layer wrapping each `Tool` impl for the engine's dispatch loop. |

## Capability

| Crate | Description |
|---|---|
| `kod-provider` | Provider trait, streaming primitives, retry policy, `TokenUsage`, `testkit` mock providers. |
| `kod-provider-anthropic` | Anthropic Messages API — SSE streaming, cache-control headers, beta gating. |
| `kod-provider-openai` | OpenAI Chat Completions — SSE streaming, tool calling, structured outputs. |
| `kod-ast` | Tree-sitter parsing for 8 languages, with a process-global parse cache. Powers the repo map. |
| `kod-risk` | Command blast-radius classification: parse shell lines, assign `RiskLevel`, flag destructive ops. |
| `kod-schema-dialect` | Per-provider JSON Schema translation and sanitization (dropping unsupported keywords). |
| `kod-minimize` | Shell-output minimizer: head/tail truncation, structured summarisation, `git diff` reduction. |
| `kod-tools` | Tool implementations: `read_file`, `write_file`, `patch_file`, `bash`, `grep`, `web_fetch`, `internal_url` handlers. |
| `kod-skills` | `SKILL.md` parser, matcher (trigram + description-token scoring), and watcher. |
| `kod-memory` | Multi-layer short-term and long-term memory store (redb) with embedding-backed retrieval. |
| `kod-lsp` | Minimal Language Server Protocol client: spawn, diagnostics, code actions. |
| `kod-mcp` | Minimal Model Context Protocol client over stdio: server registration, tool discovery. |
| `kod-swarm` | Multi-agent collaboration: agent communication hub, blackboard, worktree management, yield queue. |
| `kod-telemetry` | OTLP GenAI tracing, span helpers, context injection. |
| `kod-stats` | Session statistics: cost, latency, cache hit rate, per-tool usage. |

## Interface

| Crate | Description |
|---|---|
| `kod-cli` | The `kod` binary: argument parsing, subcommands (`serve`, `checkpoint`, `models`, `init`, `completions`, `update`, …), `fixtures` harness. |
| `kod-tui` | Terminal UI: `KodApp` state, `TuiLoop` event loop, chat widget, syntax highlighting, keybinding table. |

<Aside type="note">
  The **Engine** crates live under `crates/kod-core-*` and form a layered
  subsystem. `kod-core` depends on all five; the sub-crates do not depend
  on `kod-core`. That keeps incremental compilation fast and makes each
  subsystem independently testable.
</Aside>
