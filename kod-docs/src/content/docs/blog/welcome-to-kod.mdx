Most terminal coding agents assume two things: that you are comfortable streaming your repository to a hosted API, and that you don't mind installing a Node or Python runtime just to execute shell and file tools.

KOD (`v0.1.28`) ships as a single Rust executable built specifically for local inference servers.

## The Goal

We wanted a terminal UI agent that talks to Ollama, LM Studio, MLX, or vLLM over OpenAI-compatible HTTP endpoints while keeping every line of source code on the local machine. It needed real workspace tools, bounded context memory, and explicit file permissions rather than unrestricted shell execution.

## The Architecture

`cargo build --release` produces one binary containing the TUI, the streaming tool-calling loop, the memory store, and 27 built-in tools.

## What it cost

Designing around local 7B and 14B models exposed failure modes that rarely happen with large cloud APIs. Smaller models frequently emit slightly malformed JSON in tool arguments or lose track of file state if the system prompt is too verbose. We spent significant time trimming tool definitions, surfacing real-time context percentage in the TUI, and building retry parsers for near-valid tool calls.

<Aside type="caution" title="Limitations">
KOD is bound by your local hardware's token generation speed and context window. On machines without enough unified memory or VRAM to run at least a quantized 7B–14B coding model, multi-step edits will be noticeably slower than cloud-hosted agents.
</Aside>

## Getting started

```bash
cargo build --release
kod tui
```

See the [5-minute quickstart](/tutorials/quickstart/) to point KOD at an Ollama instance and run your first local edit.
