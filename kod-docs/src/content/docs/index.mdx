## One binary, twelve crates, zero clouds

KOD ships as a single Rust executable that runs the agent loop, the tools, the memory store, and the terminal UI. There is no Node runtime, no Python interpreter, and no Docker daemon in the path — just `cargo build --release` and a model server you control.

  <div class="stat" role="listitem"><span class="num">12</span><span class="lbl">crates in the workspace</span></div>

## Built for people who read their own diffs

KOD is designed around one question: *where does my code go when I run this?* Every design decision — from the local model default to the JSONL session log — exists so that the answer is always “nowhere you did not choose.”

<div class="kod-features not-content">

<div class="feat">
  <span class="icon"><svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><path d="M12 2 3 6v6c0 5 4 8.4 9 10 5-1.6 9-5 9-10V6l-9-4Z"/><path d="m9 12 2 2 4-5"/></svg></span>
  <h3>Policy before every tool call</h3>
  <p>Read-only, standard, or yolo presets, layered with a committed <code>.kod/policy.toml</code>: per-tool allow/deny/ask, path globs, and command allowlists. Deny always wins.</p>
</div>

<div class="feat">
  <span class="icon"><svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><path d="M2 12s3.5-7 10-7 10 7 10 7-3.5 7-10 7-10-7-10-7Z"/><circle cx="12" cy="12" r="3"/></svg></span>
  <h3>Auditable by design</h3>
  <p>Every tool call is recorded as JSONL. <code>kod replay</code> re-runs a session's tool calls without the model, so you can verify any session against the codebase at any later commit.</p>
</div>

<div class="feat">
  <span class="icon"><svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><path d="M4 19.5A2.5 2.5 0 0 1 6.5 17H20"/><path d="M6.5 2H20v20H6.5A2.5 2.5 0 0 1 4 19.5v-15A2.5 2.5 0 0 1 6.5 2Z"/></svg></span>
  <h3>Markdown skills, hot-reloaded</h3>
  <p>Drop a Markdown file with YAML front matter into <code>~/.kod/skills</code> and the next prompt sees it. Triggers, tags, capabilities, and examples — no rebuild, no restart.</p>
</div>

<div class="feat">
  <span class="icon"><svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><ellipse cx="12" cy="5" rx="8" ry="3"/><path d="M4 5v6c0 1.7 3.6 3 8 3s8-1.3 8-3V5"/><path d="M4 11v6c0 1.7 3.6 3 8 3s8-1.3 8-3v-6"/></svg></span>
  <h3>Layered memory on disk</h3>
  <p>Short-term FIFO context plus a persistent <code>redb</code> long-term store — global or project-scoped. You can open the file, inspect it, or delete it.</p>
</div>

  <p><code>kod swarm</code> decomposes a goal into subtasks, runs up to 8 agents concurrently, detects file conflicts, and asks the model to merge the results.</p>

## Up and running in five commands

<Tabs>
<TabItem label="Build from source">
  ```bash
  git clone https://github.com/elcoosp/kod.git
  cd kod && cargo build --release

  ollama serve &            # or LM Studio, MLX, vLLM, …
  ollama pull qwen3.8:27b-mlx

  ./target/release/kod doctor
  ./target/release/kod profile use local-fast
  ./target/release/kod tui
  ```
</TabItem>
<TabItem label="Try the CLI first">
  ```bash
  # one-shot agent run against a goal
  kod agent -g "add a doc comment to every public function in src/lib.rs"

  # a swarm of 4 agents on something bigger
  kod swarm -g "implement and test a rate limiter" -n 4

  # replay a recorded session as a regression check
  kod replay ~/.kod/sessions/1730000000000.jsonl --execute
  ```
</TabItem>
</Tabs>

<Aside type="tip">
  Not sure whether your setup works? <code>kod doctor</code> prints a diagnostics report for config, endpoint, skills, memory, and git in one shot.
</Aside>
